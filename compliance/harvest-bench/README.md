# Harvesting benchmark: EDC's own federated-catalog crawler vs. `crates/crawler`

Full report: [`../harvest-benchmark-2026-08-27.md`](../harvest-benchmark-2026-08-27.md).

Measures both systems with their background harvesting loop actively
re-crawling two real EDC 0.18.0 participants (3 + 7 datasets) **while**
the system's own catalog-serving endpoint is under k6 load - not
harvesting and serving measured in isolation, per this round's own task
brief.

## Layout

- `edc-fedcat-runtime/` - a real Eclipse EDC 0.18.0 *federated-catalog
  crawler* runtime (`org.eclipse.edc:federatedcatalog-base-bom:0.18.0` +
  `iam-mock`, from Maven Central, no vendored source touched), analogous
  in spirit to `../crawler-edc-fixture/` but running EDC's own harvesting
  component instead of a participant's control-plane. `HarvestSeedExtension`
  seeds its `TargetNodeDirectory`; `run-fedcat-crawler.sh` launches it,
  same env-var-driven pattern as `../crawler-edc-fixture/run-instance.sh`.
- `participants.toml` - `crates/crawler` config pointing at the same two
  participants (`requires_dcp = false`, `interval_secs = 5`).
- `catalog-request.k6.js` - the load-test script, generalized from
  `../benchmark-2026-08-27.md`'s own (adds `METHOD`/`BODY` env vars so the
  same script drives EDC's Management API `POST v3/catalogs/request` and
  this project's own `GET /catalog` - it no longer serves a DSP catalog
  endpoint at all, see the report's DSP-serving-removal note).
- `sample-rss-cpu.sh` - the 1s-interval `/proc` RSS/CPU sampler, same
  method as `../benchmark-2026-08-27.md` / `../benchmark-dcp-2026-08-27.md`.
- `check_catalog.py` - correctness check: queries either system's
  catalog-serving endpoint and asserts the aggregated result contains
  exactly the 10 expected dataset ids.
- `run-harvest-bench.sh` - the end-to-end driver. Starts the two new
  HARVEST-D/E participants (via `../crawler-edc-fixture/run-instance.sh`,
  unmodified), then runs each system under test in turn (EDC's crawler,
  then this project's `ds-catalog-broker-rs` with `CRAWLER_CONFIG_PATH` set),
  sampling RSS/CPU and running k6 while each system's harvest loop keeps
  running, checking correctness before and after each load-test window,
  and tearing everything down (trap-based cleanup) even on failure.
- `results/` - gitignored, regenerated by every run. The report captures
  the numbers and key excerpts inline.

## Re-running it

```bash
cd compliance/harvest-bench
./run-harvest-bench.sh
```

Prerequisites: same as `../crawler-edc-fixture/` (JDK 21, network access to
Maven Central for the first Gradle resolution) plus `k6` and `python3` on
`PATH`, and `cargo build --release -p ds-catalog-broker-rs` buildable from the repo
root (the driver script does this itself if needed).

Fresh, non-overlapping port block used by this round (none of it collides
with the existing EDC-A/B/C fixture instances at
`18901-18961`/`19001-19061`/`19101-19161`):

| Component | BASE_PORT | Key port |
|---|---:|---|
| HARVEST-D (3 datasets) | 19201 | DSP 19221 |
| HARVEST-E (7 datasets) | 19301 | DSP 19321 |
| EDC federated-catalog crawler | 19401 | Management API 19411 |
| `ds-catalog-broker-rs` (Rust) | - | 19501 |
